# Reflection

## Learning Outcomes
- Learned how **GOTO** works in PL/SQL and why it is discouraged.  
- Practiced replacing GOTO with structured IF/ELSE logic.  
- Built modular functions for salary, tax, years of service, and department name.  
- Integrated functions into a **Payroll Validator** for real‑world payroll checks.  

## Challenges
- Encountered `ORA-01403: no data found` when querying non‑existent employees.  
  Solved by adding exception handling.  
- DBMS Output was not enabled by default.  
  Solved by activating the DBMS Output panel in SQL Developer.  
- Illegal GOTO jumps caused compilation errors.  
  Solved by restructuring labels outside IF blocks.  

## Professional Workflow
- Started with table setup and sample data.  
- Built small GOTO programs to understand procedural jumps.  
- Transitioned to functions for modular design.  
- Integrated functions into a **Payroll Validator** for business validation.  
- Documented everything in README and reflection for clarity.  

## Key Insight
GOTO is useful for demonstration but not practical in professional systems.  
Functions and structured logic are the foundation of reliable, maintainable PL/SQL code.  
This assignment reinforced the importance of **modularity, error handling, and clarity** in database programming.
